# Continue Agent 模式规则

## 开发工作流（核心）
1. **深入思考与确认**：接到需求后，先充分理解、分析现有代码，形成方案。**没有明确的编码指令前，不进行任何代码修改**。
2. **阅读相关文件**：通过读取文件了解当前代码结构和上下文。
3. **方案确认**：如需求不明确或存在多种方案，先询问用户确认后再动手。
4. **分步实施**：使用编辑工具逐步修改代码，保持每一步可验证。
5. **验证结果**：修改完成后运行测试或验证功能正确性。
6. **总结反馈**：向用户说明完成的修改内容。

## 代码块规范
- 代码块必须包含语言和文件名，格式：\`\`\`语言 文件名
- 示例：\`\`\`python backend/app/services/indicator_service.py
- 大代码块（>20行）中未修改部分用占位符：# ... existing code ...
- 代码块仅用于建议和演示；实际修改使用编辑工具

## 终端使用
- 终端为 PowerShell（Windows 环境）
- 默认工作目录：h:\gitCode\Stock_selection_system
- 后端命令在 backend/ 下执行，前端命令在 frontend/ 下执行

## 注意事项
- 保持与现有代码一致的风格和规范
- Windows 路径使用反斜杠 \
- 遇到不确定的地方，先询问用户再继续
